標準セーブとMODデータ

ADMLは独立した「SAVE + MODS」ボタンではなく、ゲーム本体の標準セーブ導線を中心に扱います。ゲーム側の Export save、Import save、Export save as file、Import save from file がMOD対応版へ拡張されている場合、ゲーム進行とMOD環境を同じバックアップ単位で扱えます。

保存されるMOD情報

データ 内容
インストール済みMOD manifest、ZIP内ファイル一覧、plugin.jsなどの配布コード
有効化状態 次回起動時に有効化するMODのID一覧
MOD storage api.storage.set() で保存したJSON互換の設定・進行データ
エンドゲーム状態 ADMLが提供するカスタムリソース・レイヤーの保存データ

MODデータはゲームのセーブ文字列・セーブファイルの拡張領域に格納します。通常のゲームセーブだけを扱う旧版と互換性を保つため、拡張領域がないセーブはゲーム本体のデータとして読み込み、MOD領域があれば追加で検査します。

エクスポート

ゲームの標準 Export save または Export save as file を使用してください。MODを導入していない場合もゲーム本体のセーブは通常どおり出力できます。MODが導入されている場合は、MODのmanifest、コード、有効状態、保存設定が拡張領域へ追加されます。

セーブにコードが含まれるため、ファイルサイズは通常のセーブより大きくなることがあります。信頼できるバックアップ先だけに保存し、公開チャットへ無検査で貼り付けないでください。

インポート

Import save または Import save from file を実行すると、MOD領域を含むセーブでは次の確認を表示します。

このセーブには外部MODコードが含まれている可能性があります。信頼できないコードはゲームデータを読み取り、画面を書き換え、任意の処理を実行する可能性があります。内容を検査して信頼できる場合だけインポートしてください。

キャンセルを選んだ場合は、ゲームデータとMODデータのどちらも適用しません。承認した場合は、manifestとファイル一覧を確認した後、必要なMODだけを有効化してください。インポートしただけで安全性が保証されるわけではありません。

互換性と失敗時の扱い

状況 推奨処理
MOD領域がない旧セーブ ゲーム本体のセーブとして読み込む
manifestが壊れている MOD領域を拒否し、ゲーム本体データのみを保持する
依存MODが不足している 依存MODを無効化し、理由を表示する
API互換性がない MODを有効化せず、必要バージョンを表示する
未知のフィールドがある 破棄せず保留し、既知の領域だけを処理する

最初に現在のセーブを別ファイルへバックアップしてから、外部セーブをインポートしてください。サイトデータを消去すると、ローカルに保存されたMOD環境や設定が失われる場合があります。
